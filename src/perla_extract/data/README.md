# Data Directory

This directory contains extraction results and ground truth data used for training, optimization, and evaluation of the Perla Extract pipeline.

## Directory Structure

```
data/
├── extractions/          # Extraction results from various sources
│   ├── humans/          # Human-annotated extractions
│   │   ├── Consensus/   # Consensus extractions between different human annotators
│   │   ├── Bear/        # Individual human annotator (anonymized)
│   │   ├── Bee/         # Individual human annotator (anonymized)
│   │   └── ...          # Additional anonymized human annotators
│   ├── claude-opus-4-1-20250805/  # LLM model extractions
│   ├── gpt-4o-2024-08-06/         # LLM model extractions
│   └── ...              # Additional LLM model extraction folders
└── ground_truth/        # Manually checked and corrected gold standard data
    ├── dev/             # Development set used to build and optimize the pipeline
    └── test/            # Test set used to evaluate the pipeline
```

## Extractions

The `extractions/` directory contains structured data extracted from scientific papers about perovskite solar cells. Each subdirectory represents a different extraction source:

### Human Extractions (`extractions/humans/`)

- **Consensus/**: Contains consensus extractions that represent agreement between different human annotators. These are used as a reference for human performance evaluation.
- **Individual Annotators**: Folders with anonymized names (e.g., Bear, Bee, Dove, etc.) contain extractions made by individual human annotators. These are used to study inter-annotator agreement and human performance variability.

### LLM Model Extractions

Folders named after LLM models (e.g., `claude-opus-4-1-20250805/`, `gpt-4o-2024-08-06/`) contain extractions generated by different language models. These are used to:
- Compare model performance
- Evaluate extraction quality
- Benchmark against ground truth and human performance

## Ground Truth

The `ground_truth/` directory contains manually checked and corrected extractions that serve as the gold standard for evaluation:

- **dev/**: Development set used during pipeline development and optimization. This data was used to:
  - Build the extraction pipeline
  - Optimize prompts and parameters
  - Tune model configurations

- **test/**: Test set used for final evaluation of the pipeline. This data was:
  - Held out during development
  - Used to evaluate model performance
  - Used to compare against human performance

## File Format

All extraction files are JSON files following the Perla Extract data schema. Each file is named using the paper's DOI (e.g., `10.1002--adfm.201500335.json`).

## Usage

### Reviewing ground truth against the source PDFs

The shared `ground_truth/review_metadata.json` records article type, tandem
scope, review status, and notes separately from the extraction schema. Reviews,
perspectives, News & Views pieces, and papers that contain tandem devices are
excluded from benchmark scoring automatically.

Launch the local review workbench from the repository root:

```bash
.venv/bin/python review_workbench/server.py \
  --pdf-dir /Users/kevinmaikjablonka/Downloads/test_eval_pdfs
```

Then open `http://127.0.0.1:8765`. The workbench shows the PDF beside the
ground truth/model output, searches extracted PDF text with page links, edits
ground-truth JSON, and saves review classifications. It also provides:

- per-field review checkoffs with page, quote, and reviewer notes;
- automatic page suggestions for numeric values and key material/process names;
- a scan of unit-bearing PDF quantities not matched by value to the JSON;
- named reviewers with independent decisions and disagreement highlighting;
- paper-level and field-level discussion comments;
- explicit Test/Development dataset switching and corpus counts;
- a selected-cell context card with composition, architecture, metrics, and
  layer stack;
- structured missing-cell, missing-value, missing-layer, and wrong-value
  reports with resolution notes; and
- an **Add paper** flow for a PDF plus initial ground-truth JSON.

Field evidence is stored under `ground_truth/evidence/{split}/`. Reviewer and
discussion data is stored under `ground_truth/collaboration/`. These are
server-side, Git-reviewable records; the reviewer selector is an identity aid
for a trusted local team and is not password-based authentication.

See `docs/ground-truth-workflow.md` for the data/scoring lifecycle and the
recommended path from this local file-backed workbench to a Vercel deployment.

### Evaluating Model Performance

Compare model extractions against the test set:

```bash
perla-extract evaluate src/perla_extract/data/extractions/claude-opus-4-1-20250805/ src/perla_extract/data/ground_truth/test/
```

### Evaluating Human Performance

Compare human consensus extractions against the test set:

```bash
perla-extract evaluate src/perla_extract/data/extractions/humans/Consensus/ src/perla_extract/data/ground_truth/test/
```

### Comparing Individual Annotators

Compare individual human annotator extractions:

```bash
perla-extract evaluate src/perla_extract/data/extractions/humans/Bear/ src/perla_extract/data/extractions/humans/Consensus/
```
